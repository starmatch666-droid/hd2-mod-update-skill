# 03 · 只读探针与锚点重算（B/C 类）

## 什么时候需要

日志里出现这些，且当前构建的锁已经刷新过：

- `not_found` / `anchor_mismatch` / `waiting_for_entity_locator` → **B 类**（`owner_rva` 变了）
- `template_mismatch` / `ldld_block_not_found` / `guard_failed` → **C 类**（记录序号/映射/行字节变了）

## 探针是什么

一个**只读** addon：只用 `VirtualQuery` + `ReadProcessMemory`，不写内存、不调游戏引擎。
它做两件事：

1. `scout_section …`：枚举所有可读区段（拿 game.dll 各节）；
2. `scout_FOUND_DIRECT new_rva=0x… old_rva=0x… component=…`：
   对每个已知组件，在节里搜索"指针槽"指纹（用该组件在旧构建里的行上下文做守卫），
   命中即报出**新的 RVA**；顺带 `table_found`/`table_bytes` 把拣到的整张表 dump 进日志。

```bash
python tools/hd2update.py probe build --out out/probe
# 退出游戏 → out/probe/9ba626afa44a3aa3.patch_0 放到 data/ 下一个空槽位（+ .stream/.gpu_resources 两个空文件）
# 进游戏（兵营即可）1~2 分钟 → %LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\OwnerScout.log
python tools/hd2update.py probe parse "<…>/OwnerScout.log" -o probe.json
```

## 用探针结果改 mod

```bash
python tools/hd2update.py anchors src/spec.lua src/reference.json         --probe probe.json --component WeaponDataComponent --dry-run
```

工具会把源码里的 `owner_rva` 换成新值，并（当探针同时给出了 owner 与 table 地址时）
算出新的 `candidate_slot = table_addr - owner_base`。
`record_index`/`hashmap`/行 hex 这类模板常量，改完后再跑一次上机验证看是否还需要重算。

## 写自己的探针时的坑

- `ffi.cdef` 一定包 `pcall`，结构体用**唯一名**。多个 addon 共享同一个 Lua 状态：
  你声明了通用名 `_MEMORY_BASIC_INFORMATION`，别人未加保护的 cdef 就会报
  `attempt to redefine '_MEMORY_BASIC_INFORMATION'` → **对方 addon 加载失败**（我们真踩过）。
- 扫描要**分帧做预算**（例如每帧 3 ms），否则掉帧；命中即停，别整场扫。
- 只读：不要 `VirtualProtect`、不要 `WriteProcessMemory`，避免和反作弊硬碰。
- 日志一次写清楚：`标签 key=value …`，解析端只按行正则取，别依赖顺序。
